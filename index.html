The Basics

Git is a tool on your computer that saves versions of your code. Think of it as unlimited "undo" with a full history.

GitHub is a website that stores your Git projects online, so you can back them up, share them, and work with other people.

Repository

A project folder tracked by Git. Also called a "repo".

Commit

A saved snapshot of your files, with a message.

Branch

A separate line of work, so you can try things safely.

Remote

The copy of your repo on GitHub.

Setup

  1. Create a free account at github.com.
  2. Install Git from git-scm.com.
  3. Tell Git who you are (run once):
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main

Check that it works:

git --version
git config --list

Logging in to GitHub

When you push, GitHub needs to know it's you. Passwords don't work for Git anymore. Choose one:

  • Easiest: install GitHub CLI and run gh auth login.
  • Git Credential Manager: comes with Git for Windows and opens a browser sign-in on your first push.
  • SSH keys: more setup, but no repeated logins.

Your First Repository

Create a folder, turn it into a repo, save a file, and push it to GitHub.

Step 1: Create the repo locally

mkdir my-project
cd my-project
git init

Step 2: Add a file and commit

echo "# My Project" > README.md
git status
git add README.md
git commit -m "Add README"

Step 3: Create an empty repo on GitHub

Click New repository on GitHub, give it a name, and create it (don't add any files).

Step 4: Connect and push

git branch -M main
git remote add origin https://github.com/YOUR-NAME/my-project.git
git push -u origin main
💡 After the first push, you only need git push.

Not sure about the steps? Practice them in the terminal below.

The Daily Workflow

Once a repo exists, most days look like this:

git pulledit filesgit statusgit add .git commit -m "..."git push

Useful checks

git status          # what changed?
git diff            # see the exact changes
git log --oneline   # list past commits

Writing good commit messages

❌ Bad
"stuff"
"fix"
"asdf"
✅ Good
"Add login form"
"Fix crash when name is empty"
"Update README install steps"

Start with a verb, keep it short, and say what changed.

Branches

A branch lets you work on a feature without touching the main code.

git branch                  # list branches
git switch -c my-feature    # create and switch
# ...edit files, add, commit...
git switch main             # go back to main
git merge my-feature        # bring the feature in
git branch -d my-feature    # delete it

Merge conflicts

If two branches change the same line, Git can't choose for you. The file will look like this:

<<<<<<< HEAD
Title from main
=======
Title from my-feature
>>>>>>> my-feature
  1. Open the file and keep the version you want.
  2. Delete the <<<<<<<, ======= and >>>>>>> lines.
  3. Run git add on the file, then git commit.

Undo Mistakes

Everyone makes mistakes. Git helps you fix them.

ProblemFix
Edited a file and want it backgit restore file.txt
Added a file by mistakegit restore --staged file.txt
Typo in the last commit messagegit commit --amend -m "New message"
Last commit was wrong (keep the changes)git reset --soft HEAD~1
Undo a commit already pushedgit revert <commit-id>
Need to switch tasks, not ready to commitgit stash then later git stash pop
⚠️ git reset --hard deletes your changes for good. Avoid it until you are sure.

.gitignore & README

Some files should never go to GitHub: passwords, big folders, system files. List them in a file called .gitignore:

node_modules/
.env
*.log
.DS_Store
Thumbs.db
⚠️ Never commit passwords, API keys or tokens. If you do, change them right away, because deleting the file does not remove it from history.

A good README has

  • The project name and one sentence about what it does
  • How to install and run it
  • A screenshot or example
  • How to contribute and the license

Write it in Markdown:

# Title
## Section
- list item
**bold**  *italic*  `code`
[link text](https://example.com)

Pull Requests

A pull request (PR) asks the owner of a project to review and merge your changes.

  1. Fork the repo (button at top right) to get your own copy.
  2. Clone your fork to your computer.
  3. Create a branch, make changes, commit, and push.
  4. On GitHub, click Compare & pull request.
  5. Write a clear title and description, then submit.
git clone https://github.com/YOUR-NAME/some-project.git
cd some-project
git switch -c fix-typo
# ...make your change...
git add .
git commit -m "Fix typo in README"
git push -u origin fix-typo

Good PR habits

  • Keep it small and focused on one thing.
  • Explain what changed and why.
  • Reply to review comments and push fixes to the same branch.
  • Be kind and patient in reviews.

Tip: write Fixes #12 in the description to close issue 12 automatically when the PR merges.

Issues, Projects & Actions

🐞 Issues

Track bugs, ideas and questions. Use labels like bug and good first issue.

📋 Projects

A kanban board (To do, Doing, Done) built from your issues.

⚙️ Actions

Run tests or deploy automatically when you push.

💬 Discussions

A friendly space for questions and talking with the community.

⭐ Stars & Forks

Star to bookmark a project. Fork to copy it to your account.

🔒 Branch protection

Require reviews before anything merges into main.

A tiny GitHub Actions example

Save as .github/workflows/hello.yml:

name: Hello
on: push
jobs:
  say-hello:
    runs-on: ubuntu-latest
    steps:
      - run: echo "Hello from GitHub Actions!"

GitHub Pages (free website)

You can host a website straight from a repo, for free.

  1. Push a repo with an index.html file.
  2. Go to Settings → Pages.
  3. Under "Branch", choose main and / (root), then Save.
  4. After a minute your site is live at https://YOUR-NAME.github.io/REPO-NAME/.

Every time you push, the site updates by itself. This very guide can be hosted this way.

Build Your Profile

Make GitHub work as your portfolio:

  • Profile README: create a repo with the same name as your username and add a README.md. It shows on your profile.
  • Pin your best 6 repos.
  • Commit often. The green squares show your activity.
  • Contribute to open source. Search for the label good first issue.
  • Add a clear README and a screenshot to every project.
🎯 Challenge: this week, push one small project, open one issue, and make one pull request.
